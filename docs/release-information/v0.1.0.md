# v0.1.0 — first cut

`release-information` is the `minima` workspace's spec renderer, carved out as a reusable,
installable OSS package. This is the first cut: it does one thing — turn the Markdown under
`docs/release-information/` into single-file Midnight Museum HTML on every commit — and it
does it the same way in every repository that installs it.

This release note itself is the project's first dogfood: committing this `.md` file with the
bundled pre-commit hook installed produces the sibling `v0.1.0.html` and stages it
automatically into the same commit.

## Highlights

- **One CLI, five sub-commands.** `render`, `render-all`, `install`, `uninstall`, `version`.
  No flags you need to memorise; no config file; `--help` is exhaustive.
- **One pre-commit hook, one glob.** `docs/release-information/**/*.md`. Edits to any other
  Markdown file (`README.md`, `docs/blog/`, ...) are passed through untouched.
- **One HTML file per `.md`.** Inline CSS, no CDN, no `_site/` directory, no asset folder.
  The output is `cat`-able, paste-able into a Claude context window, and reviewable in a
  single GitHub diff.
- **One dark theme.** Midnight Museum: `#0F172A` ground, serif body, sans-serif heading,
  Pygments monokai for code. Inherited 1:1 from the author's `minima` workspace so the
  visual identity of the rendered HTML is identical across every project that adopts
  this OSS.

## What's included

### Core renderer (`release_information.core`)

A pure function `render_markdown(md_text, title_fallback=...)` that converts a Markdown
string to a self-contained HTML5 document. Extensions enabled: `extra`, `toc`, `codehilite`,
`sane_lists`, `admonition`. `[TOC]` is auto-inserted after the first `h1` if no explicit
marker is present. Brand strings `Release Information` / `Spec` ship as constants in
`core.theme`.

### CLI (`release_information.cli`)

- `release-information render <FILE.md>` — single file, prints output absolute path.
- `release-information render-all [--root .]` — bulk, empty matches exit 0.
- `release-information install [--repo-root PATH] [--force]` — installs the pre-commit hook;
  backs up existing hook to `pre-commit.backup` when `--force` is passed.
- `release-information uninstall [--repo-root PATH]` — restores the backup, or removes the
  hook if no backup is present.
- `release-information version` — prints `0.1.0`.

### Pre-commit hook (`release_information.hooks`)

A POSIX shell script template installed into `<repo>/.git/hooks/pre-commit`. It only acts
on staged files matching `docs/release-information/**/*.md`, calls
`release-information render` per file, and `git add`s the resulting `.html` into the same
commit.

### Tests

27 `pytest` cases across `tests/test_renderer.py`, `tests/test_cli.py`, and
`tests/test_hook_install.py`. The hook tests use `git init` in `tmp_path` so the user's real
git config and hooks are never touched.

### CI

GitHub Actions matrix on Python 3.10 / 3.11 / 3.12: `ruff check src tests` followed by
`pytest`.

## Compatibility

- Python: 3.10, 3.11, 3.12.
- OS: macOS, Linux. Windows is on the roadmap (the bundled hook is a POSIX shell script).
- Markdown engine: `markdown>=3.5,<4` and `pygments>=2.17,<3` are pinned to keep the
  rendered HTML stable across installs.

## Known limitations

- The default theme is not yet configurable; multi-theme switching is on the roadmap.
- No `pre-commit` framework integration (`.pre-commit-hooks.yaml`) yet — the bundled shell
  hook is the only path. Repos already using the `pre-commit` framework can either skip
  `release-information install` and call `release-information render` from their own hook,
  or wait for the framework integration in a later release.
- No PyPI release yet; install from the GitHub source URL until then (see `README.md`).

## Upgrade notes

This is the initial release; no upgrade path applies. From v0.2.0 onwards, any change to
the rendered HTML output (inline CSS, brand strings, `[TOC]` placement) will be called out
explicitly in `CHANGELOG.md` so downstream repositories know when a re-render diff is
expected.
